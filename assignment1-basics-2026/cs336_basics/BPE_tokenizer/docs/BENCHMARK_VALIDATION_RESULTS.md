# TinyStories 验证集：naive BPE 基准

日期：2026-09-15。使用用户编写的 `BPE_tokenizer.py`，训练算法未修改。

## 配置

- 机器：Apple M5，10 个 CPU 核心，24 GiB 内存。
- 环境：macOS 26.6.2 arm64，Python 3.12.14。
- 数据：完整 `TinyStoriesV2-GPT4-valid.txt`，22,502,601 bytes（约 21.46 MiB）。
- 词表上限：10,000，包括 256 个基础字节和 `<|endoftext|>`。
- 预分词：5,419,001 次片段出现，汇总为 13,111 种不同片段。
- 数据 SHA-256：`6874bae9a4c1a4e7edcf0e53b86c17817e9cf881fc75ff2368da457b80c0585d`。
- 训练实现 SHA-256：`0eae63fb18ddb99b4999d7a43d18b5aad8826d6ba4ffaf0a1ac598b8b8b2ce5b`。

## 普通运行结果

以下为一次未启用 cProfile 的实测，没有与另一项训练并行运行。

| 阶段 | 耗时 | 占总训练时间 |
| --- | ---: | ---: |
| 初始化词表 | < 0.001 秒 | < 0.01% |
| 读取文件 | 0.043 秒 | 0.08% |
| 预分词与计数 | 2.831 秒 | 5.34% |
| 合并训练 | 50.106 秒 | 94.58% |
| 总训练时间 | **52.980 秒** | 100% |

峰值进程 RSS 为 **119.84 MiB**。计时不含 Python 启动、模块导入与结果保存；峰值 RSS 则包括解释器与导入模块。

最终得到 10,000 个词表条目和 9,743 条有序合并规则。最长 token 为 **`b' accomplishment'`，15 bytes，ID 7427**。
它是一个英文单词加上前导空格；空格来自 GPT-2 预分词规则，属于合理结果。

已核对保存结果中的 256 个基础字节、特殊 token、连续编号、每条合并的两个来源 token，以及合并结果与对应新增词表条目的一致性。

## cProfile 定位

另用同一份完整验证集和相同参数单独运行 cProfile；总时间为 145.693 秒，约为普通运行的 2.75 倍。
以下函数耗时来自这次受分析工具影响的运行，用于定位瓶颈，不能作为普通运行的阶段耗时。

| 函数 | 调用次数 | 累计耗时（含子调用） |
| --- | ---: | ---: |
| `merge_pair` | 127,740,473 | 91.415 秒 |
| `count_pair` | 9,743 | 30.115 秒 |
| `pretokenize_and_count` | 1 | 5.975 秒 |

`13,111 × 9,743 = 127,740,473`：当前每轮对所有不同片段调用 `merge_pair`，包括不含目标 pair 的片段。
重复计数则在每一轮重新遍历所有片段内部的相邻位置。应先减少这些重复处理，再考虑其他优化。

两次运行的 `vocab.json`、`merges.json` 和训练源码快照逐字节一致，输入数据 SHA-256 也一致。

## 优化方向

当前验证集基准的主要瓶颈是合并阶段。即使把预分词时间理想化地降为零，本次运行最多也只能省下 2.83 秒。
因此下一步优先维护 `pair → 包含它的片段` 索引及全局相邻对频次，只对受影响片段应用合并、增量更新频次。
仍需从全局频次表选出下一轮规则，并保持同频时取字典序最大 pair 的规则。

之后再按特殊 token 边界切分语料，用 `multiprocessing` 分担预分词工作，将各进程的片段频次按键相加。
每轮 BPE 合并依赖上一轮的结果，不能把不同轮次独立同时训练。完整训练集上的瓶颈比例需要重新测量。
